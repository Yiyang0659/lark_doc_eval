## 🎯 评分维度概览

### 四大核心维度

| 维度 | 权重 | 满分 | 说明 |
|------|------|------|------|
| 📈 实际价值 | 30% | 5分 | 文档是否真正落地并产生价值 |
| ♻️ 可复用性 | 25% | 5分 | 文档是否可被他人复用 |
| 💡 创新性 | 25% | 5分 | 文档是否有创新点 |
| 📝 方法沉淀 | 20% | 5分 | 文档是否形成可复制的方法论 |

### 综合评分

- **满分**：20分
- **计算公式**：`实际价值×0.30 + 可复用性×0.25 + 创新性×0.25 + 方法沉淀×0.20`

### 等级划分

| 总分范围 | 等级 | 说明 |
|----------|------|------|
| 18-20分 | 🌟 卓越 | 标杆文档，强烈推荐 |
| 15-17分 | ✅ 优秀 | 高质量文档，推荐 |
| 12-14分 | 🆗 良好 | 合格文档，可优化 |
| 8-11分 | ⚠️ 一般 | 需要改进 |
| 4-7分 | ❌ 较差 | 建议重写 |

## 🚀 使用指南

### 方式一：AI自动评分

1. **输入**：提供飞书文档链接
2. **处理**：AI读取文档内容，按照评分标准进行评估
3. **输出**：按照报告模板格式生成评分报告

### 方式二：HTML Demo调用

1. **读取配置**：从`config.json`读取评分标准配置
2. **展示表单**：让用户输入文档链接
3. **调用API**：发送到后端进行AI评分
4. **展示结果**：按照报告模板格式展示评分结果

## 📊 子项评估说明

### 实际价值（4个子项）

| 子项 | 判断标准 |
|------|----------|
| 1.1 真实落地 | 文档内容是否已在实际业务/项目中应用 |
| 1.2 量化收益 | 是否有明确的数据化收益（效率/成本/周期） |
| 1.3 解决痛点 | 是否明确指出并解决了具体的业务/工程痛点 |
| 1.4 落地佐证 | 是否有可核查的证据材料 |

### 可复用性（3个子项）

| 子项 | 判断标准 |
|------|----------|
| 2.1 标准化程度 | 是否形成SOP/流程/模板/Checklist |
| 2.2 跨场景适用 | 是否支持跨团队/跨场景复用 |
| 2.3 低依赖性 | 新人能否直接上手，不依赖原作者 |

### 创新性（3个子项）

| 子项 | 判断标准 |
|------|----------|
| 3.1 新思路/算法 | 是否有创新的解决方案或算法改进 |
| 3.2 AI Coding新法 | 是否有新颖的AI辅助编程方法 |
| 3.3 新架构设计 | 是否提出新的Skill/Agent/系统架构 |

### 方法沉淀（2个子项）

| 子项 | 判断标准 |
|------|----------|
| 4.1 可复制性 | 流程/Prompt/步骤是否清晰，能否照做 |
| 4.2 完整性 | 逻辑是否闭环，步骤是否齐全 |

## 📌 注意事项

### 评分原则

1. **客观公正**：基于文档实际内容，避免主观臆断
2. **数据驱动**：优先使用量化数据作为评分依据
3. **全面评估**：覆盖所有维度和子项
4. **实用导向**：评分结果应具有实际指导意义

### 常见问题

**Q: 文档没有量化数据怎么办？**  
A: 在实际价值维度会扣分，但仍可从其他维度评估。

**Q: 创新性如何判断？**  
A: 与常见方案对比，看是否有新的思路、方法或架构设计。

**Q: 可复用性如何评估？**  
A: 看是否有标准化流程、模板，以及是否支持跨场景使用。
