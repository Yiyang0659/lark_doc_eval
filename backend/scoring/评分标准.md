# 飞书文档AI智能评分标准 V1.0

---

## 📊 评分概览

| 维度 | 权重 | 满分 | 说明 |
|------|------|------|------|
| 实际价值 | 30% | 5分 | 文档是否真正落地并产生价值 |
| 可复用性 | 25% | 5分 | 文档是否可被他人复用 |
| 创新性 | 25% | 5分 | 文档是否有创新点 |
| 方法沉淀 | 20% | 5分 | 文档是否形成可复制的方法论 |
| **综合评分** | **100%** | **20分** | 四个维度加权后总分 |

### 综合等级划分

| 总分范围 | 等级 | 说明 |
|----------|------|------|
| 18-20分 | 🌟 卓越 | 标杆文档，强烈推荐 |
| 15-17分 | ✅ 优秀 | 高质量文档，推荐 |
| 12-14分 | 🆗 良好 | 合格文档，可优化 |
| 8-11分 | ⚠️ 一般 | 需要改进 |
| 4-7分 | ❌ 较差 | 建议重写 |

## 📈 维度一：实际价值（权重30%）

### 评估核心问题
> 这篇文档是否真正产生了实际价值？能否证明它"有用"？

### 判断子项

| 子项 | 判断标准 | 评分依据 |
|------|----------|----------|
| **1.1 真实落地** | 文档内容是否已在实际业务/项目中应用 | 查找"上线"、"部署"、"已应用"等关键词及时间戳 |
| **1.2 量化收益** | 是否有明确的数据化收益（效率/成本/周期） | 查找百分比、具体数值、对比数据 |
| **1.3 解决痛点** | 是否明确指出并解决了具体的业务/工程痛点 | 开篇是否描述问题，问题是否具体可感知 |
| **1.4 落地佐证** | 是否有可核查的证据材料 | 代码链接、截图、监控数据、任务单号等 |

### 评分细则

| 分数 | 等级 | 判断标准 |
|------|------|----------|
| **5分** | 🌟 卓越 | 4项子项全部满足；有具体数据支撑；佐证材料完整可验证 |
| **4分** | ✅ 优秀 | 满足3项子项；有部分数据；有佐证但不够完整 |
| **3分** | 🆗 良好 | 满足2项子项；有落地但缺少量化；佐证材料较少 |
| **2分** | ⚠️ 一般 | 仅满足1项子项；多为理论描述；缺少实际证据 |
| **1分** | ❌ 较差 | 4项子项均不满足；纯理论/规划；无任何落地迹象 |

### 判断问题清单

```
□ 文档是否提到"已上线/已部署/已在使用"？
□ 是否有效率提升XX%、成本降低XX元等数据？
□ 是否在开头明确了要解决什么问题？
□ 是否有代码仓库链接、任务系统链接、截图等佐证？
```

## ♻️ 维度二：可复用性（权重25%）

### 评估核心问题
> 这篇文档能否被其他人直接使用或借鉴？

### 判断子项

| 子项 | 判断标准 | 评分依据 |
|------|----------|----------|
| **2.1 标准化程度** | 是否形成SOP/流程/模板/Checklist | 是否有清晰的步骤编号、流程图、模板代码 |
| **2.2 跨场景适用** | 是否支持跨团队/跨场景复用 | 方法是否具有通用性，而非绑定特定业务 |
| **2.3 低依赖性** | 新人能否直接上手，不依赖原作者 | 是否有背景说明、前置条件、常见问题 |

### 评分细则

| 分数 | 等级 | 判断标准 |
|------|------|----------|
| **5分** | 🌟 卓越 | 有完整SOP/模板；可直接套用到其他场景；新人可独立完成 |
| **4分** | ✅ 优秀 | 有较清晰流程；需少量修改即可复用；有足够上下文说明 |
| **3分** | 🆗 良好 | 有基本步骤；需要一定调整才能复用；部分需原作者补充 |
| **2分** | ⚠️ 一般 | 步骤零散；强依赖特定场景；新人需频繁请教 |
| **1分** | ❌ 较差 | 纯个人笔记；无法脱离原作者理解；不可复用 |

### 判断问题清单

```
□ 是否有清晰的1-2-3步骤或流程图？
□ 是否提供了模板代码/Prompt/配置文件？
□ 其他团队是否可以直接参考使用？
□ 新同事能否看懂并独立执行？
```

## 💡 维度三：创新性（权重25%）

### 评估核心问题
> 这篇文档是否带来了新的思路、方法或技术？

### 判断子项

| 子项 | 判断标准 | 评分依据 |
|------|----------|----------|
| **3.1 新思路/算法** | 是否有创新的解决方案或算法改进 | 与常见方案对比，是否有突破 |
| **3.2 AI Coding新法** | 是否有新颖的AI辅助编程方法 | Prompt技巧、Agent设计、工作流创新 |
| **3.3 新架构设计** | 是否提出新的Skill/Agent/系统架构 | 架构是否新颖，是否解决了传统方案的痛点 |

### 评分细则

| 分数 | 等级 | 判断标准 |
|------|------|----------|
| **5分** | 🌟 卓越 | 开创性方法；对团队有重大启发；可引发技术方向变革 |
| **4分** | ✅ 优秀 | 显著创新；解决已有方案的痛点；具有较高推广价值 |
| **3分** | 🆗 良好 | 有一定创新点；在现有基础上改进；有参考价值 |
| **2分** | ⚠️ 一般 | 创新较少；组合现有方法；略有优化 |
| **1分** | ❌ 较差 | 无创新；常规方法应用；无额外价值 |

### 判断问题清单

```
□ 是否提出了前所未有的方法或思路？
□ 是否对现有方案有显著改进？
□ AI相关的使用方法是否有新意？
□ 是否能给团队成员带来启发？
```

## 📝 维度四：方法沉淀（权重20%）

### 评估核心问题
> 这篇文档的方法论是否完整、可复制？

### 判断子项

| 子项 | 判断标准 | 评分依据 |
|------|----------|----------|
| **4.1 可复制性** | 流程/Prompt/步骤是否清晰，能否照做 | 关键步骤是否有具体示例，输入输出是否明确 |
| **4.2 完整性** | 逻辑是否闭环，步骤是否齐全 | 是否覆盖：问题→方案→步骤→验证→总结 |

### 评分细则

| 分数 | 等级 | 判断标准 |
|------|------|----------|
| **5分** | 🌟 卓越 | 完美可复制；逻辑闭环；覆盖全生命周期；可作为标准参考 |
| **4分** | ✅ 优秀 | 高度可复制；步骤完整；仅少量细节需补充 |
| **3分** | 🆗 良好 | 基本可复制；有部分缺失；需一定经验补充 |
| **2分** | ⚠️ 一般 | 难以直接复制；步骤不完整；需大量补充 |
| **1分** | ❌ 较差 | 无法复制；仅为零散想法；逻辑不完整 |

### 判断问题清单

```
□ 关键步骤是否有具体的Prompt/代码示例？
□ 是否有清晰的输入输出说明？
□ 是否覆盖：背景→问题→方案→实施→验证→总结？
□ 是否包含踩坑记录和注意事项？
```

### 完整性检查清单

| 环节 | 说明 | 必选/可选 |
|------|------|----------|
| 问题定义/痛点 | 明确要解决什么问题 | 必选 |
| 方案选择/定位 | 为什么选择这个方案 | 必选 |
| 实施步骤 | 具体怎么做 | 必选 |
| 效果验证 | 如何验证效果 | 必选 |
| 最佳实践 | 使用建议 | 推荐 |
| 踩坑记录 | 常见问题和解决方案 | 推荐 |
| 版本信息 | 更新记录 | 可选 |

## 📊 加权计算公式

```
综合得分 = 实际价值得分 × 0.30 + 可复用性得分 × 0.25 + 创新性得分 × 0.25 + 方法沉淀得分 × 0.20
```

### 计算示例

假设四个维度得分分别为：5, 4, 4, 5

```
综合得分 = 5 × 0.30 + 4 × 0.25 + 4 × 0.25 + 5 × 0.20
         = 1.50 + 1.00 + 1.00 + 1.00
         = 4.50/5
         = 18.00/20
```

## 🔍 AI评分Prompt模板

以下Prompt用于指导AI进行文档评分：

```
你是一个专业的文档质量评估专家。请根据以下评分维度和标准，对提供的飞书文档进行详细分析并打分。

## 评分维度和标准：

### 1. 实际价值 (1-5分)
评估子项：
- 文档内容是否真实落地
- 是否有量效收益（效率/成本/周期数据化）
- 是否解决明确的业务/工程痛点
- 是否有可核查的落地佐证材料

### 2. 可复用性 (1-5分)
评估子项：
- 是否形成SOP/流程/模板，思路可借鉴
- 是否支持跨团队、跨场景复用
- 是否不依赖个人能力，新人可直接接手

### 3. 创新性 (1-5分)
评估子项：
- 是否有新算法/新思路，能给团队启发
- 是否有新的AI Coding落地方法
- 是否有新的Skill/Agent/架构设计

### 4. 方法沉淀 (1-5分)
评估子项：
- 可复制性：流程/Prompt/步骤清晰，别人能直接照做
- 完整性：逻辑闭环、步骤齐全，不是零散点子
```
